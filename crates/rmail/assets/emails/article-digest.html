The case for native rendering

A 4-minute read · by the rMail engineering team

For years, desktop apps reached for bundled browser engines to render rich content. The trade-off was obvious: hundreds of megabytes and a sluggish start, all to draw some text and images.

A leaner path

Every modern OS already ships a capable, well-maintained web engine — WebKit on macOS, WebView2 on Windows. By rendering e-mail through the system engine, we get correct HTML, native text selection and hardware-accelerated scrolling for essentially zero binary cost.

"The fastest code is the code that ships with the operating system."

What this means for you

  • Faster cold starts and a smaller download.
  • Pixel-accurate rendering that matches the rest of your system.
  • Security patches that arrive with OS updates, not app updates.

There are trade-offs, of course — we give up some control over layout edge cases. But for reading mail, meeting people where their OS already is feels like the right call.
